# 品类路由：3C 数码

> 本卡只决定达人形象方向、钩子角度、镜头套路。语言、转化、支付、监管以 [`../markets/`](../markets/) 下对应市场卡为准。

## 1. 品类识别特征

产品图上出现以下线索时归入本类：

- 有屏幕、按键、指示灯、接口、散热结构
- 有线材、充电口、吸附结构、卡扣
- 配件类：支架、保护壳、线缆、转接头、耳机、充电宝
- 表面以金属、塑料、硅胶、织物为主，常有品牌 logo

特征：以桌面或手持为使用场景，功能需要通过操作演示才能讲清。

## 2. 达人形象方向

| 项目 | 方向 |
|---|---|
| 年龄段 | 25–38 岁 |
| 性别呈现 | 按产品定位选择；通用配件类中性化处理 |
| 气质 | 干净利落、有理性的分享感，不做夸张惊喜 |
| 穿着风格 | 简洁纯色上衣、衬衫或针织。避免花纹复杂的衣服抢画面 |
| 手部状态 | 指甲干净、修剪整齐。操作演示类内容手是主角 |
| 与产品的关系 | 正在试用并分享观察，**不得**宣称长期使用数据或效果 |

## 3. 场景与光线

按可信度排序：

1. **书桌 / 居家办公角**——首选。桌面有真实使用痕迹（笔记本、杯子、线材）
2. **床头的充电区域**——适合充电类、床头配件
3. **咖啡厅桌边**——适合便携类产品，但环境光复杂，生成难度高

光线要求：室内环境光为主。屏幕类产品要注意屏幕亮度与环境的平衡——屏幕过曝会丢失内容，环境过暗会显得刻意。

## 4. 钩子角度优先级

1. **好奇型**（最有效）——用功能演示的第一帧制造停留。「这东西能这样用」是本类最强的钩子
2. **痛点型**——点名具体困扰（线乱、电量焦虑、设备放不稳）
3. **反差型**——使用前后的状态对比（桌面从乱到整、从不够用到够用）
4. **真实体验型**——平视分享发现感

## 5. 镜头语言套路

本品类验证有效的结构：

```text
产品全貌 → 接口或结构细节特写 → 关键功能演示 → 实际使用场景 → 产品全貌收口
```

关键细节：

- **不要在开场就给特写**。数码产品需要先让观众看清整体长什么样，再进入细节
- **功能演示必须完整**。一个动作从开始到结果要在一个镜头内完成，跳切会让观众怀疑真实性
- **接口与按键是本类的可信度抓手**。给一个清晰的接口特写，比任何形容词都有效
- 最后一镜回到整体，与开场形成呼应

## 6. 卖点表达重点

| 卖点类型 | 怎么表达 | 用什么镜头证明 |
|---|---|---|
| 功能 | 用动作展示而非参数罗列 | 特写：操作过程与结果 |
| 兼容性 | 展示连接到另一设备 | 中景：两台设备同时入镜 |
| 便携 | 尺寸与携带场景 | 中景：手持、放进包或口袋 |
| 做工 | 描述材质与接缝 | 大特写：接口、边角、表面纹理 |
| 稳定性 | 描述使用中的稳固表现 | 近景：产品承托设备的状态 |

**参数类卖点（容量、功率、续航）不要写进口播台词**——观众记不住数字，也不信。改成可看见的结果。

## 7. 常见翻车点

| 问题 | 原因 | 规避写法 |
|---|---|---|
| 屏幕内容乱码或变形 | 生成模型无法稳定渲染界面内容 | **不要描述屏幕显示的具体内容**。用「屏幕亮起」这类模糊表述，或让屏幕转向侧面 |
| 接口与按键数量错位 | 细节缺乏锁定 | 在提示词中明确接口位置与数量，并放入约束层 |
| 线材走向不合理 | 物理逻辑理解不足 | 减少线材入镜；必要时机位避开线材根部 |
| logo 变形或错误 | 文字渲染不稳定 | 不要在提示词里描述 logo 文字内容，只描述 logo 的位置与形状 |
| 充电指示灯颜色错 | 细节漂移 | 若产品有此特征，在约束层写明 |
| 手部与设备比例失真 | 缺少尺寸锚点 | 每个镜头描述手与设备的相对大小 |

## 8. 默认参数建议

- 时长：15 秒（功能复杂的产品用 30 秒）
- 镜头数量：15 秒 4 个；30 秒 6 个
- 画面比例：9:16
- 卖点数量：1–2 个（数码产品一个功能讲透比罗列三个更有效）
