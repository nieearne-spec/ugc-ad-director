# 生成反馈迭代（工作流第 5 步）

第一次生成就能直接用，是例外不是常态。**交付提示词只是策划的结束，不是项目的结束。**用户拿着穿帮的成片或截图回来时，进入本环节。

## 一、先定位，再改词

拿到反馈后，先对照下表定位失效的约束，**不要一上来就重写提示词**：

| 穿帮现象 | 失效环节 | 去哪修 |
|---|---|---|
| 产品比参照物大/小（如垫子比手机大） | 尺寸锁写成了绝对尺寸 | [`product-lock.md`](product-lock.md) 三点五节：改相对参照 |
| 产品细节铺满整面、数量不对（吸盘铺满、颗粒数错） | 计数类约束，模型数不对 | [`product-lock.md`](product-lock.md) 三点五节：改拓扑关系，细节改一瞥 |
| 产品形状、颜色、结构漂移 | 约束层不足或被截断 | [`seedance-prompt.md`](seedance-prompt.md) 常见问题表 |
| 人物换脸、发型服装变化 | 未用参考图或权重不足 | [`seedance-prompt.md`](seedance-prompt.md) 常见问题表 |
| 镜头之间场景对不上（桌面、墙、光线变了） | 场景无锚点 | [`reference-images.md`](reference-images.md)：加场景参考图 @image3，或拆段生成 |
| 手部多指、动作僵死 | 手部精细动作过多 | [`shots.md`](shots.md) 风险分级：简化该镜动作 |
| 台词口型对不上 | 模型不支持该语言变体 | 更换模型或缩短单句 |

## 二、最小修改纪律

**一次只改引发问题的那一条约束，其余原样保留。**全盘重写会把已经验证OK的部分一起改漂，返回去都不知道哪里变好了。

- 改之前把当前版本存档（方案包目录里留 `seedance-prompt-v1.txt`、`-v2.txt`……）
- 改完在方案包里记一行：哪个镜头、什么现象、改了哪句
- 约束层只增不删：为修问题新加的锁，下一版继续保留

## 三、生成策略（按成本从低到高）

1. **单镜测试**：全片生成前，先只测风险分级最高的那一镜（标记见 [`shots.md`](shots.md)）。核心演示镜、换道具镜、手部动作多的镜是高发区。单镜通过再出全片。
2. **整片重抽**：约束没改、只是随机翻车时，先原样重抽 2–3 次。视频生成有随机性，不全是提示词的锅。
3. **拆段生成 + 剪辑拼接**：整片生成反复漂移时，按镜头拆成单段分别生成（每段都带完整的风格层 + 该镜描述 + 约束层 + 全部参考图），剪辑软件拼接。单段生成时参考图权重更集中。**拆段必须配场景参考图**，否则段与段之间场景对不上。

## 四、改词还是换抽法（决策规则）

| 情况 | 动作 |
|---|---|
| 问题稳定复现（每次都在同一处崩） | 提示词问题，按本文件第一节改词 |
| 问题随机出现（有时好有时坏） | 先重抽，不改词 |
| 同一镜头改了两次还崩 | 不是改词能解决的——按第三节改生成方式（单测/拆段），或按 [`shots.md`](shots.md) 重设计该镜（避开不可锁细节） |

## 五、教训回流

迭代中发现的**可复用规律**（不是本产品特有的问题），按性质沉淀回规则库并提交推送：

- 尺寸、计数、细节展示类 → [`product-lock.md`](product-lock.md)
- 锚点与参考图类 → [`reference-images.md`](reference-images.md)
- 提示词结构与语言分层类 → [`seedance-prompt.md`](seedance-prompt.md)
- 镜头设计类 → [`shots.md`](shots.md)

只沉淀规律，不沉淀个例。**改完规则库立即 commit + push**，不要依赖本地副本。
